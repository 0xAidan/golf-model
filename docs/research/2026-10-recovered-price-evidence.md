## CLV: preserve prices, disqualify the close assumption

The frozen server has **83,463 CLV rows**, but only **662 distinct complete price/outcome tuples**, **139 distinct entry-price contracts**, and **two events**: Bank of Utah (30,278 rows) and Baycurrent (53,185). A complete tuple here is `(tournament_id, player_key, bet_type, market_book, odds_taken_decimal, closing_odds_decimal, outcome)`. Of the rows, 83,454 belong to repeated tuples; one tuple occurs 897 times. Recorded dates are October 5–16, not original quote timestamps. All prices are finite decimals above one; 6,057 outcomes are null. Stored legacy CLV agrees with its old formula throughout.

Named entry books include BetOnline, FanDuel, Pinnacle, Betcris, Bovada, BetMGM and others. They should not be discarded because another table contains synthetic prices. However, the stored close is not qualified:

- [`src/datagolf.py:1795`](../../src/datagolf.py#L1795) `fetch_closing_odds()` calls **current** `betting-tools/outrights` for four markets with no historical event/year/book argument. It averages numeric entry fields above one rather than selecting a verified closing quote from the entry book. Its docstring claims closing behavior the request does not implement.
- [`src/learning.py:1438`](../../src/learning.py#L1438) post-review matches that result to historical picks using player/market only. It does not verify returned event identity, capture before market start, preserve the source response, or deduplicate repeated reviews. The same function treats exact American `+100` differently from `+101`, because conversion uses `>100`/`<-100`; this is another reason not to infer exact quote provenance from legacy stored decimals.
- `clv_log` contains no pick ID, opponent, lane, model/config hash, settlement contract, original taken time, close time or source response ID. `created_at` is the insertion time. Thus **zero rows are currently established same-event, same-book, pre-start close pairs**. This is a qualification finding, not a claim that every entry price is false.

A diagnostic same-source key join to frozen picks finds 79,072 compatible CLV rows, but 51,682 have multiple possible picks and 4,391 have none. Such a join cannot supply missing historical provenance. No rows in this audit establish actual book execution, stake, payout or account receipts.

The additive CLV API now retains every legacy field and stored row, exposes the arithmetic `100*(taken/recorded_close-1)`, and returns `qualified_clv_pct=null`, `close_verified=false`, `source_qualification=unverified_legacy_close`. For 3.0 versus 2.5 the ratio is +20%; that identity alone does not prove closing value or fair EV. No de-vig or significance claim is added. Ten CLV tests and targeted Ruff passed.

A source-local exact join can improve coverage, but nearest-time or current-config attribution would invent evidence. `picks` and `pick_outcomes` supply grading, not proof of execution.

## The missing historical market baseline is obtainable

Current `historical_odds` has 96,261 rows (49,537 DG-Base, 46,724 DG-CH); hidden local has 327,935 (169,159 DG-Base, 158,776 DG-CH). Both historical matchup tables are empty. These are vendor prediction-derived synthetic prices, not sportsbook closes. [`backtester/backfill.py:257`](../../backtester/backfill.py#L257) explicitly creates them from the predictions archive; its assertion that the vendor lacks historical bookmaker odds is incorrect.

[DataGolf's API contract](https://datagolf.com/api-access) documents separate historical outright and matchup endpoints with opening/closing prices and bet outcomes. Use explicit `tour`, `event_id`, **calendar** `year`, `book` and format; outright requests also require `market`. Use `historical-odds/event-list` for available identities, not defaults to the most recent event. `betting-tools/*` provides current prices. Coverage must be verified per response; the linked [coverage page](https://datagolf.com/api-historical-coverage) has an old update date and does not establish 2026 availability. A successful empty response is missing coverage, not zero edge.

## Concrete next experiment

1. **Append a versioned quote/source ledger.** Preserve raw response bytes/hash, safe request parameters, acquisition time, vendor update time when supplied, vendor event metadata and canonical `(tour,event_id,calendar_year)`. Store every book/side, original odds format, selected quote time, market start/round, tie/dead-heat/withdrawal rules, source ID and parsing version. Never overwrite the legacy CLV/prediction tables.
2. **Backfill a bounded real-price audit first.** Request the historical event list, then one known completed event/book/market through `historical-odds/outrights`; independently test `historical-odds/matchups`. Preserve rows and metadata even when timing/rules are missing. Check IDs, names, both sides, line ordering and outcomes before scaling. An archive's open/close endpoint alone does not prove a model could transact at an arbitrary reconstructed decision time.
3. **Recover the useful observed cohorts.** Map Truist payload display names against its source-local field/player IDs with an explicit ambiguity report; retain the six strict keyed rows separately. Join exact snapshot IDs and full market keys for lane comparisons. Keep Bermuda sealed for forward scoring. Evaluate published selections separately from the dense observation universe, which mixes accepted and failed candidates.
4. **Train an event-weighted market residual challenger.** Predict decisive tournament matchup outcomes using a regularized correction to a two-sided no-vig market logit, with prior-event SG/skill differences and calibrated uncertainty. Freeze features and decision-time quotes; fit calibration on prior chronological events only. Keep placements separate until settlement probabilities are modeled. Compare market-only, original frozen model and residual model on the same event/contract/quote cohort using log loss, Brier and calibration; use event-block uncertainty. Repeated snapshots cannot be separate folds or inflate sample size.
5. **Score price and outcome evidence separately.** Qualified CLV requires a verified event/contract/book close before the market starts; fair-close EV additionally requires a defensible margin/settlement model. Policy returns require a fixed ex-ante selection/sizing/settlement specification and must be labeled hypothetical unless execution receipts exist. The current recovered cohorts are useful for replay and pipeline validation but span too few independent events to establish profitable market superiority or justify promotion.

Implementation hooks are `scripts/backfill_matchup_odds.py` (already stores tie rules and open/close times), the incorrect synthetic-only `backtester.backfill.backfill_odds`, `_build_market_prediction_rows` in `backtester/dashboard_runtime.py` (identity and raw-side capture), `pick_ledger` (model provenance), and the additive qualification API in `src/clv.py`. No model mathematics or promotion gates changed in this audit.
